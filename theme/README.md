## Files

- `assets/lullyrest.css` — scoped styles on the locked Direction C tokens. Everything is namespaced `.lr-` so it cannot leak into Elixir's components.
- `snippets/lullyrest-kink-diagram.liquid` — the recurring "kinked cable" mechanism diagram, inline SVG. Mirrors `brand/assets/kinked-cable-diagram.svg` but **drops that file's `prefers-color-scheme` block**: the storefront background is theme-controlled, so reacting to the visitor's OS theme would invert the strokes into invisibility on a light page.
- `snippets/lullyrest-zones.liquid` — the four-zone breakdown, shared by the block and section versions so the spec exists once.
- `blocks/lullyrest-mechanism.liquid`, `blocks/lullyrest-zones.liquid` — theme blocks for use *inside* Elixir's `listicle` and `cs-content` containers.
- `sections/lullyrest-*.liquid` — standalone section versions for the PDP.
- `sections/lullyrest-proof-placeholder.liquid` — reserved social-proof slots, deliberately empty and labelled.
- `templates/page.presell.json`, `templates/product.lullyrest.json` — generated by `build_templates.py`.
- `templates/page.neck-pain-listicle.json` — generated by `build_listicle_neckpain.py`. A second, separate listicle page (own template/handle), not a replacement for `presell`. Uses only stock Elixir `listicle`/`customer-reviews-carousel` block types — no custom `lullyrest-*` blocks — so it needs no vendor-schema patching. Unlike `build_templates.py`, its generator writes straight into this repo's `templates/` folder (no `THEME`/`REPO` env vars needed) since it isn't touching a live pull.
- `templates/product.lullyrest-close.json` — generated by `build_pdp2.py`. A brand-new, close-focused PDP (BOGO buy box, free-gift kit, 4 social-proof slots, condensed problem-to-fix section) — **separate from and does not replace** `product.lullyrest.json`. Uses only stock Elixir block types (`shop-product-details`'s `quantity_break`/`premium_attachment_kit`, `statistics-grid`, `alternating-features`, `product-benefits`, `store-faq`, `satisfaction-guarantee`, `sale-countdown-banner`, `sticky-add-to-cart`) plus the existing custom `lullyrest-proof-placeholder` section for reserved `[EMPTY]`-labeled social-proof slots — no vendor-schema patching needed. Not yet bound to any product (`build_pdp2.py`'s generated template exists on the draft theme, but the core pillow product's `templateSuffix` is still `lullyrest`). See `docs/superpowers/plans/2026-08-21-pdp-rebuild-bogo-cart.md` and `PROGRESS.md` (2026-08-21).
- `build_pdp2.py` — the generator for the above. Follows `build_templates.py`'s pattern (`stock()`/`add()`/`rebuild_blocks()`/`block_of()`/`put()` helpers, same `LR_THEME`/`LR_REPO` env-var convention) but is a fully separate script — does not import from or modify `build_templates.py`.
- `patch_cart_drawer.py` — one-off script that adds block instances (`cart_progress_bar`, `cart_upsell` ×4, `cart_timer_bar`) to `config/settings_data.json`'s `current.sections["cart-drawer"]` entry, which previously had none. Note: `settings_data.json` ships with a leading `/* ... */` comment header (same pattern as `templates/product.json`) that must be stripped before `json.loads` and re-prepended on write — the script handles this.

## Vendor patches (not tracked — reapply after any re-pull)

`build_templates.py` patches two Elixir files so our blocks are selectable inside them. Both edits only append to the schema `blocks` array:

- `sections/listicle.liquid` → accepts `lullyrest-mechanism`, `lullyrest-zones`
- `blocks/cs-content.liquid` → accepts `lullyrest-mechanism`, `lullyrest-zones`

**If you re-pull the theme, these patches are lost.** Re-run `build_templates.py` to reapply.

## Deploying

```bash
shopify theme pull  --store gcvy0q-cb.myshopify.com --theme 163498656002 --path /tmp/draft-theme
python3 build_templates.py          # copies our files in, patches vendor schemas, regenerates templates
shopify theme push  --store gcvy0q-cb.myshopify.com --theme 163498656002 --path /tmp/draft-theme --nodelete \
  --only "templates/page.presell.json" --only "templates/product.lullyrest.json" \
  --only "sections/lullyrest-*" --only "blocks/lullyrest-*" --only "snippets/lullyrest-*" \
  --only "assets/lullyrest*" --only "sections/listicle.liquid" --only "blocks/cs-content.liquid"
```

Push blocks **before** templates that reference them — Shopify rejects a template whose block types don't yet exist on the theme.

`page.neck-pain-listicle.json` is deployed: pushed to the draft theme, and bound to page `gid://shopify/Page/136642101506` (handle `neck-pain-listicle`, `isPublished: false`). See `PROGRESS.md` (2026-08-21) for the deploy log. Note for future edits to this template: Shopify's `richtext` setting sanitizer only permits `<p>/<ul>/<ol>/<h1-6>` as top-level nodes and strips `style` attributes and `<div>`/`<span>` entirely — a first push attempt with inline-styled placeholder boxes was rejected for this reason; the generator now uses plain `<p><strong>[LABEL]</strong> ...</p>` instead.

`build_templates.py`'s `THEME`/`REPO` constants are machine-specific absolute paths (currently set for a prior Mac session) — update them to your local pull directory and this `theme/` folder's path before running.

## Gotchas hit while building this

- Theme block/preset `name` is capped at **25 characters**. "LullyRest mechanism diagram" (27) was rejected.
- `listicle-item.image` and `cs-image.image` are `image_picker` — they resolve **Shopify Files**, not theme assets. The four product renders are uploaded to Files as `lullyrest-{hero,side,top,cross}.png` and referenced as `shopify://shop_images/…`. The same PNGs also exist in `assets/` for our own sections, which use `asset_url` instead.
- `themeDuplicate` returns `newTheme`, not `theme`.
- `shopify theme pull --path` requires the directory to already exist.
- A `theme pull` run immediately after `themeDuplicate` can silently return an incomplete (assets-only) tree even though it reports success — the server-side duplicate may not be fully copied yet. Re-run the pull (scoping with repeated `--only "<dir>/*"` flags helped) and verify `config/`, `layout/`, `sections/`, etc. actually landed before running `build_templates.py`.
- On Windows, `open()` without `encoding="utf-8"` in `build_templates.py` raises `UnicodeEncodeError` on the em-dashes/arrows in the copy (Python defaults to the OS codepage, not UTF-8) — already fixed in the script.
